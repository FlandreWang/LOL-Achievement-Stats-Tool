# 英雄列表内容优化 - 技术方案

## 1. 技术选型

- Vue 3 Composition API（已有）
- Pinia stores：`useRecordStore`、`useAchievementStore`（已有）
- Tailwind CSS 样式（已有）

## 2. 架构设计

改动集中在 `HeroListCard.vue` 组件内部，不涉及新增组件。数据流：

```
HeroList.vue
  └─ HeroListCard.vue
       ├─ 缩略区：hero.roles（角色标签）+ recordStore（进度条）
       └─ 展开区：achievementStore + recordStore（逐项成就状态）
```

## 3. 数据结构

缩略区进度条使用已有数据：
- `recordStore.records[heroId]` → 统计已完成数
- `achievementStore.achievements.length` → 总数

展开区逐项成就：
- 遍历 `achievementStore.achievements`，对每个成就调用 `recordStore.getRecord(heroId, achId)` 获取完成状态

## 4. 接口设计

`HeroListCard` 组件接口变更：

| Prop | 当前 | 变更 |
|------|------|------|
| `achievements` | 外部传入（从未被使用） | 删除，改为内部从 store 计算 |

新增内部 computed：
- `heroAchievements`：`achievementStore.achievements.map(ach => ({ ...ach, ...recordStore.getRecord(hero.heroId, ach.id) }))`
- `completedCount`：统计已完成数量（从 heroAchievements 计算）
- `progressPercent`：完成百分比

## 5. 核心逻辑

### 缩略区布局调整

当前缩略区结构：
```
[头像] [名称/称号] [完成状态badge] [展开按钮]
```

调整为：
```
[头像] [名称/称号 + 角色标签] [进度条] [展开按钮]
```

- 角色标签放在名称下方，使用 flex-wrap 自动换行
- 进度条放在信息区右侧，竖向对齐

### 展开区调整

- 移除角色标签（已移至缩略区）
- 替换为逐项成就列表：每行显示成就名称 + 完成状态
- 调整 Transition 的 max-h 限制，支持更多内容

## 6. 文件结构

| 文件 | 操作 | 说明 |
|------|------|------|
| `packages/frontend/src/components/hero/HeroListCard.vue` | 修改 | 主要改动文件 |
| `packages/frontend/src/components/hero/HeroList.vue` | 无需修改 | 不再需要传 achievements prop |

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| 成就数量多时展开区过高 | 设置 max-h 并允许 overflow-y-auto |
| 缩略区空间紧张（角色标签+进度条） | 角色标签紧凑排列，进度条使用最小宽度 |
